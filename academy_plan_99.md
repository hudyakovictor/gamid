# SIGNAL ARENA — Академия решений
## План теоретического раздела v2.0 — уровень 99/100

> Рынок не обязан объяснять, почему ты ошибся.  
> Он просто принимает твоё решение и отправляет квитанцию.

Этот документ — план оглавления и контентная система для раздела **Теории / Академии** SIGNAL ARENA.

Главная задача: сделать обучение не курсом трейдинга, не туториалом по игре и не коллекцией красивых терминов, а **операционной системой рыночного решения**.

Игрок должен не “знать слова”. Игрок должен уметь:

```text
увидеть факт;
отделить его от шума;
собрать гипотезу;
задать инвалидацию;
выбрать действие;
защитить риск;
объяснить уверенность;
перенести навык в скрытый сценарий Arena.
```

# 0. Доктрина Академии

## 0.1. Что такое теория в SIGNAL ARENA

**Академия решений** — это не библиотека справок и не “университет свечных паттернов”.

Это отдел внутреннего расследования.

Он отвечает на один вопрос:

```text
Почему игрок решил именно так — и было ли это решение качественным до того,
как рынок показал будущее?
```

## 0.2. Чему Академия учит

Академия учит не торговле “в плюс”.

Она учит процессу:

```text
Факт → Интерпретация → Гипотеза → План → Инвалидация → Действие → Разбор
```

Если игрок получает прибыль плохим способом, Академия не аплодирует.

Она говорит:

> Поздравляем.  
> Рынок временно спонсировал вашу ошибку.  
> Не превращайте это в метод.

## 0.3. Чему Академия не учит

Запрещено превращать теорию в:

```text
- финансовый совет;
- обещание доходности;
- список сигналов “покупай/продавай”;
- курс “100 паттернов технического анализа”;
- мотивационный шум;
- объяснение игровых кнопок вместо аналитического мышления;
- фэнтезийную боёвку карт против монстров.
```

Карты — не магия.  
Сущности — не враги на поле.  
Рынок — не босс.  
Босс — твоя неоформленная гипотеза.

# 1. Стиль теории

## 1.1. Голос Академии

Тон: **панк-таблоидная криптосатира + сухой учебный протокол**.

Текст должен звучать так, будто:

```text
жёлтая газета нашла твой торговый дневник;
риск-менеджер устал повторять очевидное;
рынок уже знает концовку;
игрок узнает её последним.
```

## 1.2. Формула фразы

```text
Драматичный заголовок
+ простая рыночная правда
+ неприятный вывод для игрока
```

Примеры:

```text
ПРИБЫЛЬ НЕ ДОКАЗЫВАЕТ ПРАВОТУ.
Иногда рынок платит за плохие идеи.
Обычно авансом.
```

```text
НОВОСТЬ НЕ ЯВЛЯЕТСЯ СИГНАЛОМ.
Сигналом является реакция рынка.
Заголовок просто громко просит твои деньги.
```

```text
СТОП НЕ ДЛЯ БОЛИ.
Стоп для момента, где идея умерла.
Если идея умерла раньше тебя — поздравляем, это уже прогресс.
```

## 1.3. Правила текста

Каждая статья обязана быть:

```text
короткой по фразам;
плотной по смыслу;
жёсткой к ошибкам;
понятной новичку;
полезной продвинутому игроку;
связанной с Decision Sheet;
связанной с игровым score;
связанной с Arena-практикой.
```

Шутка разрешена только если она объясняет механику.

Плохая шутка:

```text
Рынок хаотичный, ха-ха.
```

Хорошая шутка:

```text
Рынок хаотичный.
Поэтому твой стоп в центре шума выглядит не как риск-менеджмент,
а как добровольная передача ликвидности.
```

## 1.4. Запрещённая вода

В теории нельзя писать:

```text
“Торгуйте по тренду”.
“Важно соблюдать дисциплину”.
“Используйте риск-менеджмент”.
“Нужно контролировать эмоции”.
“Ищите хорошие точки входа”.
```

Так пишут курсы, после которых человек знает слова и всё равно нажимает Long в пасть к FOMO.

Вместо этого:

```text
Плохо:
Соблюдайте дисциплину.

Хорошо:
Если после убытка ты увеличил риск,
новый сценарий уже не про рынок.
Он про попытку вернуть самооценку через кнопку Buy.
```

# 2. Универсальный шаблон каждой статьи

Каждая глава Академии пишется по одному формату. Это защищает контент от воды и превращает теорию в тренировку решения.

## 2.1. Структура статьи

```text
1. Таблоидный заголовок
   Короткая фраза, которая вскрывает боль темы.

2. Рыночная проблема
   Какая реальная ошибка возникает без этого навыка.

3. Главное правило
   Один принцип, который игрок может применить в новом сценарии.

4. Что считать фактом
   Какие наблюдаемые данные можно использовать как evidence.

5. Что не считать доказательством
   Шум, мнение, нарратив, пересказ, эмоция, одиночная свеча.

6. Мини-алгоритм анализа
   3–7 шагов: что открыть, что сравнить, что записать.

7. Как это меняет план
   Long / Short / Wait / No Trade, entry, stop, invalidation, target, confidence.

8. Связь с SIGNAL ARENA
   Source Groups, Cards, Protocols, Scenario Formats.

9. Как это проверяется в игре
   Что система смотрит в Decision Trace.

10. Критерии высокого score
   Какие scoring dimensions затрагиваются.

11. Плохой ответ / средний ответ / 99-балльный ответ
   Игрок должен увидеть разницу между шумом и качественным решением.

12. Rematch-задание
   Как навык тренируется повторно в другом контексте.

13. Финальный удар
   Одно короткое правило, которое можно запомнить.
```

## 2.2. Пример мини-формата внутри статьи

Тема: ложный пробой.

```text
ПРОБОЙ ОБЪЯВЛЕН. ПОДТВЕРЖДЕНИЕ НЕ ЯВИЛОСЬ.

Пробой уровня — это факт.
Прибыльный Long — это ещё не факт.

Проверь:
1. Где был уровень?
2. Было ли закрепление?
3. Был ли объём?
4. Удержал ли рынок ретест?
5. Где идея Long отменяется?

Плохой ответ:
“Цена пробила сопротивление. Long. Уверенность 90%.”

99-балльный ответ:
“Пробой есть, но закрепления и объёма нет. Старший контекст остаётся диапазонным.
Enter Now некачественный. Выбираю Wait for Retest. Long появится только при удержании зоны.
Инвалидация: возврат под уровень и слабая реакция покупателей. Confidence 55%.”

Финальный удар:
Если пробой не может пережить ретест, это был не пробой.
Это была экскурсия за твоими стопами.
```

# 3. Лестница освоения

Каждый навык проходит 5 стадий.

```text
1. Theory
   Игрок понимает принцип.

2. Controlled Practice
   Игрок применяет принцип в явном учебном контексте.

3. Exam
   Тема известна, но точная угроза скрыта.

4. Arena Transfer
   Тема смешана с другими. Подсказок нет. Сущность молчит.

5. Mastery / Collection
   Навык статистически подтверждён в разных режимах, активах и давлениях.
```

## 3.1. Уровни внутри каждой главы

```text
Beginner:
Видит базовый факт.

Intermediate:
Связывает факт с гипотезой.

Advanced:
Строит альтернативный план и инвалидацию.

Mastery:
Переносит навык в другой актив, режим, таймфрейм или серию после стресса.
```

Рынок не выдаёт дипломы.  
Он выдаёт повторяющиеся ситуации, пока игрок не перестанет быть учебным материалом.

# Модуль 0. Decision Foundations / Фундамент решения

> ПРИБЫЛЬ НЕ АЛИБИ.  
> Иногда рынок просто не успел тебя наказать.

## Цель модуля

Научить игрока отличать **качество решения** от **рыночного исхода**.

## Learning outcomes

После модуля игрок умеет:

```text
1. Разделять факт, интерпретацию, гипотезу и мнение.
2. Обосновывать Long / Short / Wait / No Trade.
3. Формулировать инвалидацию до входа.
4. Подбирать уверенность под качество evidence.
5. Не считать прибыль доказательством правильного процесса.
6. Заполнять Decision Sheet без нарративного мусора.
```

## Главы

```text
0.1. Хорошее решение ≠ хороший исход
0.2. Long, Short, Wait, No Trade: четыре законных действия
0.3. Факт, интерпретация, гипотеза, мнение: отделение костей от супа
0.4. Evidence Only: доказательство должно наблюдаться, а не нравиться
0.5. Иерархия evidence: цена, структура, объём, контекст, источник
0.6. Инвалидация до входа: где идея умирает
0.7. Risk-First Mode: сначала риск, потом желание
0.8. Confidence Check: индекс веры в график
0.9. Decision Sheet на 99 баллов
```

## Игровая реализация

```text
Source Groups: PRICE, CONTEXT по необходимости.
Cards: Evidence Only, Define Invalidation, No Trade Is a Decision, Confidence Check.
Protocols: Risk-First Mode, Discipline Over Profit.
Entities: Certainty Siren, Expectancy Sphinx, FOMO Wraith, System Breaker.
Scenario formats: Pre-Entry, Blind, простые Conflict.
```

## Scoring focus

```text
Evidence quality
Hypothesis logic
Stop/invalidation logic
Protocol adherence
Confidence calibration
Discipline
```

## Mastery gate

Игрок проходит модуль не когда прочитал главы, а когда в Exam:

```text
- минимум 3 раза выбирает Wait/No Trade при слабом evidence;
- не завышает confidence при неполных данных;
- формулирует инвалидацию до направления;
```

# Модуль 1. Price Structure / Рыночная структура

> СВЕЧА НЕ ГОВОРИТ.  
> Она оставляет улики.  
> Остальное додумывает толпа.

## Цель модуля

Научить игрока видеть рынок как структуру, а не как набор эмоциональных палок на экране.

## Learning outcomes

```text
1. Определять тренд, диапазон и переходный режим.
2. Читать HH/HL, LH/LL и слом структуры.
3. Отличать структурный сигнал от шума.
4. Строить зоны, а не поклоняться точным линиям.
5. Связывать entry, stop и target со структурой.
```

## Главы

```text
1.1. Свеча — не сигнал, а след сделки
1.2. Тренд, диапазон, переход: три режима, три набора рисков
1.3. HH/HL и LH/LL: кто контролирует цену
1.4. Слом структуры или шум: как не принять фитиль за революцию
1.5. Уровни как зоны: рынок не обязан уважать твою линию
1.6. Принятие и отвержение цены
1.7. Entry Zone: вход зоной, а не молитвой на одну цену
1.8. Когда структура говорит “Wait”
1.9. Что структура не может доказать без контекста
```

## Игровая реализация

```text
Source Groups: PRICE.
Cards: Market Structure, Define Entry Zone, Enter Now, Wait for Retest.
Protocols: Evidence Only, No Confirmation No Trade в отдельных уроках.
Entities: Wick Mimic, Fake Breakout Phantom, Routine Rot, Regime Shifter.
Scenario formats: Pre-Entry, Blind, Conflict.
```

## Scoring focus

```text
Context interpretation
Hypothesis logic
Entry/condition quality
Stop/invalidation logic
Target/RR quality
```

## Практика

Игрок должен перед действием отметить:

```text
- режим рынка;
- ключевые swing points;
- зону интереса;
- место, где гипотеза ломается;
- почему действие сейчас лучше, чем Wait/No Trade.
```

# Модуль 2. Breakout Validation / Проверка пробоя

> ПРОБОЙ СЛУЧИЛСЯ.  
> Поздравления преждевременны.  
> Ликвидность ещё не закончила обед.

## Цель модуля

Научить игрока не входить в каждый пробой и не путать движение с подтверждением.

## Learning outcomes

```text
1. Отличать пробой уровня от принятия новой цены.
2. Проверять объём, закрепление, ретест и продолжение.
3. Выбирать Wait for Retest вместо Enter Now при слабом confirmation.
4. Формулировать условия, при которых пробой становится рабочим планом.
5. Распознавать риск ложного пробоя и выноса ликвидности.
```

## Главы

```text
2.1. Пробой — это факт, не разрешение на Long
2.2. Анатомия пробоя: уровень, импульс, объём, закрепление, ретест
2.3. Volume Confirmation: когда объём подтверждает, а когда выдаёт ловушку
2.4. Wait for Retest: рынок должен доказать, что уровень теперь работает
2.5. Ложный пробой: рынок открыл дверь, чтобы проверить, кто побежит
2.6. Stop-Hunt: очевидная ликвидность как публичный буфет
2.7. Enter Now: когда агрессивный вход допустим
2.8. No Confirmation, No Trade: отсутствие сделки как фильтр выживания
```

## Игровая реализация

```text
Source Groups: PRICE, FLOW.
Cards: Volume Confirmation, Wait for Retest, Market Structure, No Confirmation No Trade.
Protocols: No Confirmation No Trade, Evidence Only.
Entities: Fake Breakout Phantom, Stop-Hunt Kraken, Wick Mimic, FOMO Wraith.
Scenario formats: Pre-Entry, Conflict, Blind.
```

## Scoring focus

```text
Evidence quality
Entry/condition quality
Entity resistance
Protocol adherence
Confidence calibration
```

## 99-балльная практика

Сильный игрок пишет не “пробой = Long”.

Он пишет:

```text
Пробой есть, но подтверждение слабое / подтверждение есть / подтверждение конфликтует.
Условие входа: удержание зоны или ретест.
Инвалидация: возврат под уровень и отсутствие покупателя.
Действие: Wait / Enter Now / No Trade в зависимости от evidence.
Confidence: не выше силы доказательств.
```

# Модуль 4. Risk & Invalidation / Риск и инвалидация

> МАЛЕНЬКИЙ СТОП НЕ ЗНАЧИТ МАЛЕНЬКИЙ РИСК.  
> Иногда это просто быстрая доставка денег рынку.

## Цель модуля

Научить игрока строить план от риска, а не от желания оказаться правым.

## Learning outcomes

```text
1. Отличать стоп от инвалидации идеи.
2. Ставить защиту за структурной причиной.
3. Учитывать волатильность при выборе стопа и размера риска.
4. Не увеличивать риск ради спасения гипотезы.
5. Отказываться от сделки, если риск не имеет смысла.
```

## Главы

```text
4.1. Риск — это не расстояние до стопа
4.2. Инвалидация: точка смерти идеи
4.3. Structural Stop: защита за причиной, а не за надеждой
4.4. Volatility Context: одинаковый паттерн, разная цена ошибки
4.5. Risk Cap: предел, после которого начинается ритуал самообмана
4.6. Risk Profile: aggressive, conservative, conditional, no trade
4.7. Risk/Reward: правильная идея может быть плохой сделкой
4.8. Когда лучший риск — отсутствие позиции
```

## Игровая реализация

```text
Protocols: Risk-First Mode.
```

> ЛИКВИДНОСТЬ — ЭТО НЕ МАГИЯ.

# 5. Cross-skill главы

Cross-skill главы нужны после основных модулей. Они собирают несколько навыков в один рабочий протокол.

## CS1. Confirmed Entry / Подтверждённый вход

```text
Market Structure
+ Volume Confirmation
+ Wait for Retest
```

**Задача:** входить не по импульсу, а по подтверждённой структуре.

**Практика:** сценарии с реальным и ложным пробоем.

**99-критерий:** игрок может выбрать Enter Now только при согласованности структуры, объёма, риска и инвалидации.

---

## CS2. Safe Stop / Безопасный стоп

```text
Volatility Context
+ Set Structural Stop
+ Risk Cap
```

**Задача:** ставить стоп там, где ломается идея, а не там, где не страшно потерять.

**Практика:** сценарии с разной волатильностью и одинаковым визуальным паттерном.

**99-критерий:** стоп связан со структурой, учитывает волатильность и не нарушает risk cap.

---

## CS3. Anti-FOMO Protocol / Протокол против погони

```text
Do Not Chase
+ No Trade Is a Decision
+ Out of Market Is Normal
```

**Задача:** не покупать движение только потому, что оно уже случилось.

**Практика:** сценарии, где цена уже ушла, а новая точка риска отсутствует.

**99-критерий:** игрок спокойно выбирает Wait/No Trade и формулирует условие будущего входа.

---

## CS4. Verified Narrative / Проверенный нарратив

```text
Source Quality
+ News Context
+ Evidence Only
+ Noise Quarantine
```

**Задача:** отделить событие от реакции рынка и факт от пересказа.

**Практика:** конфликтные сценарии с новостями, социальным шумом и ценовой реакцией.

**99-критерий:** игрок не использует хайп как evidence и снижает confidence при слабом источнике.

---

## CS5. Protected Position / Защищённая позиция

```text
Define Invalidation
+ No Averaging Without a Plan
+ Preserve the System
```

**Задача:** не переписывать план после входа.

**Практика:** In-Position и Series после убытка или прибыли.

**99-критерий:** игрок выбирает Hold / Reduce / Close / Invalidate по фактам, а не по боли.

# 8. Связь модулей со scoring engine

| Scoring dimension | Главные модули | Что теория должна научить делать |
|---|---|---|
| Context interpretation | 1, 3, 9, 11 | Определять режим, старший контекст, flow, macro фон |
| Evidence quality | 0, 2, 8, 10 | Отличать факт от шума, проверять подтверждение и источники |
| Hypothesis logic | 0, 1, 3, 11 | Строить условную гипотезу, а не пророчество |
| Entry/condition quality | 1, 2, 5 | Входить по условию, зоне, ретесту, подтверждению |
| Stop/invalidation logic | 0, 4, 6 | Знать, где идея отменяется |
| Target/RR quality | 4, 5 | Выбирать цель по структуре и ликвидности |
| Risk management | 4, 5, 6, 10 | Ограничивать риск до входа и внутри позиции |
| Discipline | 6, 7, 12, 13 | Не разрушать систему эмоцией, серией или турниром |
| Entity resistance | все | Распознавать скрытые повторяющиеся угрозы |
| Protocol adherence | 0, 4, 7, 13 | Соблюдать обязательные правила миссии |
| Confidence calibration | 0, 8, 9, 11, 12 | Подгонять уверенность под evidence, а не под желание |

# 9. Примеры эталонных ответов

## 9.1. Слабый ответ

```text
Цена выросла. Думаю будет продолжение. Long. Confidence 90%.
```

Диагноз Академии:

```text
Факт найден.
План не найден.
Рынок благодарит за ликвидность.
```

## 9.2. Средний ответ

```text
Цена пробила локальный уровень. Есть шанс продолжения, но я не уверен.
Поставлю стоп ниже уровня и цель выше.
Confidence 60%.
```

Диагноз:

```text
Есть направление.
Есть попытка риска.
Нет подтверждения, нет ретеста, слабая инвалидация.
Система ещё жива, но уже кашляет.
```

## 9.3. 99-балльный ответ

```text
Локальный уровень пробит, но объём не подтвердил импульс.
Старший ТФ остаётся в диапазоне, ближайшая цель слишком близко к верхней границе.
Enter Now некачественный.
Выбираю Wait for Retest.
Условие Long: цена удерживает зону пробоя, появляется объём, RR не ниже минимума.
Инвалидация идеи Long: возврат под уровень и слабая реакция покупателя.
Confidence 55%, потому что evidence смешанный.
```

Диагноз:

```text
Игрок не угадал будущее.
Игрок ограничил глупость.
Для рынка это уже неприятная новость.
```

# 10. Финальный acceptance checklist для Академии

Каждая глава проходит проверку:

```text
[ ] Глава учит реальному аналитическому действию.
[ ] В главе есть конкретный принцип, а не мотивационная фраза.
[ ] Есть “что считать фактом” и “что не считать доказательством”.
[ ] Есть связь с Decision Sheet.
[ ] Есть связь с Cards, Source Groups и Protocols.
[ ] Есть связь со scoring dimensions.
[ ] Есть плохой, средний и 99-балльный пример ответа.
[ ] Есть практика Academy / Exam / Arena.
[ ] Есть Rematch-логика.
[ ] Нет обещаний прибыли.
[ ] Нет “сигналов” без условий и инвалидации.
[ ] No Trade может быть высоким ответом.
[ ] Прибыльный плохой процесс может быть низким ответом.
[ ] Сущность не раскрывается раньше правил видимости.
[ ] Стиль мрачный, короткий, сатирический, но механика остаётся ясной.
```
